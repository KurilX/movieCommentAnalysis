# 03: 一键重跑改批量插入（3 分钟 → 秒级）

**What to build:** 把「一键重跑全库」从 28000 次单条 insert 改成批量写入，实测耗时明显下降即算成功。分析结果与方面结果的写库路径都走批量，事务语义保持「要么全旧要么全新」。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 持久层新增批量插入能力：一条 SQL 插入多行，单批上限 500 行；分析结果与方面结果两条写入路径都使用它
- [x] 不引入新的 Service 层、不使用 MyBatis-Plus 的 `saveBatch`
- [x] JDBC 连接串启用 `rewriteBatchedStatements=true`
- [x] 重跑全库仍为单事务：中途失败时数据库不会停在半新半旧状态
- [x] 不实现「双写切换/临时表改名」这类防空窗设计
- [x] 行为不变：重跑后分析结果行数不增加（覆盖而非追加），方面结果行数与六个维度一致
- [x] 测试：重跑前后 `comment_analysis` 行数相等；`comment_aspect` 行数为评论数×维度数
- [x] 测试：构造写入失败场景，断言整个重跑回滚（数据保持重跑前状态）
- [x] 实测并记录改造前后的耗时（同一批 4000 条评论），前后数字并列写进 `docs/项目状态审计.md`
- [x] 不写性能自动化测试（以实测对比为准）
