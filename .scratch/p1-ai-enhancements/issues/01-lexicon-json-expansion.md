# 01: 情感词典搬进 JSON 并扩到 300-500 词

**What to build:** 规则引擎的情感词典从 Java 硬编码搬进独立的 JSON 资源文件，词条扩充到 300-500 个（含旧词典全部 43 词），每条带极性、强度、来源域三个字段。词源两条腿：开放情感词库做底座，再从 4000 条真实评论统计高频未覆盖表达、由开发期 AI 逐条读语境判定极性补影视领域词。加载失败时快速失败并给出可读原因。用扩充后的词典（规则不动）跑出第二组评测数字。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 词典以 JSON 资源文件形式随构建打包，每条含 `word` / `polarity`（1/0/-1）/ `strength`（1/2）/ `domain`（general/film）
- [x] 词条总数落在 300-500 区间，旧词典 43 词全部保留且极性不变
- [x] 词条 JSON 一条一行格式化，diff 可读，便于论文附录引用
- [x] 高频候选词统计逻辑随仓库提交（可复跑），用于证明选词过程可复现
- [x] 引擎启动时从 JSON 加载词典，`analyze()` 不再引用硬编码集合
- [x] 加载失败语义：文件缺失 / JSON 非法 / 词条缺字段 → 启动即失败，错误信息指明具体原因；**不允许**静默降级成空词典
- [x] 词典按词长降序建索引，匹配采用最长优先，避免短词吃掉长词（如「好」吃掉「好看」）
- [x] 测试：给一条含新影视领域词（如「封神」）的评论，断言判为正面——证明读的是文件不是硬编码
- [x] 测试：文件缺失与 JSON 非法两种情况均启动失败并抛可读异常
- [x] 测试：旧词典 43 词原有判定行为不变；空文本仍抛 `IllegalArgumentException`
- [x] 用扩充后的词典 + **未改动的规则** 跑全量评测，产出「第二组」Accuracy / macro-F1 / 混淆矩阵
- [x] 第二组数字记录进 `docs/项目状态审计.md`（与基线 37.4% 并列）
